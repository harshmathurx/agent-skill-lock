# Support

Use GitHub issues for bugs, parser gaps, and docs problems.

Good issues include:

- the agent tool or platform involved
- the repo-relative file path
- a small redacted fixture
- expected lockfile behavior
- actual lockfile behavior

Do not paste real tokens, private keys, cookies, private repository config, or employer-confidential examples.

## Security reports

If the issue could leak secrets, bypass the Action check, misrepresent a lockfile diff, or cause unintended command execution, report it privately. See [SECURITY.md](SECURITY.md).

## Feature requests

The best feature requests are narrow:

- "Support this config path."
- "Extract this field into metadata."
- "Redact this value shape."
- "Make this CI failure easier to understand."

Broad requests such as dashboards, policy engines, scanner integrations, and registries may be valid, but they should explain the exact review problem first.
